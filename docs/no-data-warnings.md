# Предупреждения об отсутствии данных

Настройка относится ко всему правилу `changes`, а не к одному запросу:

```yaml
changes:
  - id: service-alpha
    attributes:
      tooltip:
        show: true
        hideNoDataWarnings: true
      metrics:
        queries:
          - { refid: A }
          - { refid: B, calculation: total }
        baseColor: green
        thresholds:
          - { value: 80, color: red }
```

По умолчанию `hideNoDataWarnings: false`: причины отсутствия данных видны.
При `true` подсказка скрывает только предупреждения о недостающих входах.
Нужен YAML boolean `true`/`false`, не строка `"true"`. Неверный тип настройки
диагностируется и не включает скрытие.

## Что скрывается, а что остаётся

| Ситуация | При `hideNoDataWarnings: true` |
| --- | --- |
| Запрос не вернул ряд или формуле не хватает входа (`MISSING_INPUT`) | Подробное no-data предупреждение скрыто |
| Пустой ряд, нет совпадений по legend/фильтру, нет строк (`EMPTY_INPUT`) | Подробное no-data предупреждение скрыто |
| Нужная расчёту точка или числовая ячейка содержит настоящий `null`/`undefined` (`MISSING_VALUE`) | Подробное no-data предупреждение скрыто |
| Источник вернул ошибку; выражение/условие сломано; значение нечисловое или бесконечное | Ошибка остаётся |
| Неверная настройка YAML, которую удалось связать с правилом | Сообщение остаётся |
| Вообще нельзя определить состояние сервиса | Серый цвет и «Нет данных для определения состояния» остаются |

Ошибки без надёжной привязки к правилу не переносятся на соседний сервис.
Синтаксически сломанный YAML также не получает выдуманной привязки. Такие
сообщения остаются в общем результате диагностики; отдельного UI-списка нет.
Явное `tooltip.show: false` по-прежнему отключает подсказку этого правила.

Если `A` красная, а у `B` данных нет, сохраняется красный цвет по `A`.
Флаг не меняет расчёт, выбор победившей метрики, цвет или значения в таблице.
Диагностика и общее пояснение no-data имеют шрифт 12px; значения метрик и
`textAbove`/`textBelow` остаются 13px. Это одинаково для hover и закреплённого tooltip.

## Как определяется нехватка значений

Алгоритмы агрегирования не меняются: плагин не пропускает `null` ради частичного
результата и не подставляет ноль или предыдущую точку.

| Расчёт | Какие точки нужны | Пример |
| --- | --- | --- |
| `last` | Последняя | `[null, 10]` → 10; `[10, null]` → no-data |
| `delta` | Первая и последняя | `[10, null, 20]` → 10; `[10, null]` → no-data |
| `total`, `min`, `max` | Все | `[10, null]` → no-data, не частичное значение 10 |
| `count` | Число позиций | `[null, null]` → 2 |
| Любой расчёт пустого ряда | Нет входов | `[]` → no-data, включая `count` |

Строка `"null"`, пустая строка, `"abc"`, `NaN` и `Infinity` — не пропуски:
если они нужны расчёту, это ошибка числового значения. Если среди нужных точек
есть и пропуск, и неверное число, ошибка не маскируется пропуском.
По сравнению с прежним поведением настоящий `null` теперь объясняется как
отсутствие данных, а не как «Расчёт не вернул конечное число».

## Причины вместо повторов

Если запрос `A` завершился таймаутом, а формулы `F` и `G` зависят от него,
tooltip показывает таймаут, а не дополнительные «нет данных» для `A`, `F`, `G`.
Это применяется только при известной связи причин; одинаковый текст или
похожее имя сами по себе связью не считаются. Все доступные входы формулы
проверяются: отсутствие первого не скрывает ошибку следующего. При нехватке
входов формула не выполняется; синтаксические ошибки всё равно диагностируются.
Ошибки, требующие фактического выполнения формулы, можно определить только
после получения её входов.

Пустой ответ или корректный фильтр без совпадений сами по себе не доказывают
ошибку конфигурации. Например, по отсутствию ряда нельзя надёжно отличить
опечатку `refid` от запроса, временно не вернувшего данные.

## Полный JSON

Флаг фильтрует только tooltip. Полный JSON-снимок сохраняет все диагностики,
исходные настройки, доступные значения и связи с запросами/правилами.
В [контракте v2](capture-contract.md) скрытые в UI сообщения по-прежнему доступны
клиентам API; исходные временные точки не добавляются.

Сценарии и ссылки на автоматические проверки: [N01–N33 в каталоге](test-cases.md#предупреждения-об-отсутствии-данных).
