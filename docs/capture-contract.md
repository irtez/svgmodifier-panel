# Контракт снимка SVG Modifier v1

Снимок описывает **одно завершённое обновление панели**: настройки, результаты
расчётов, ошибки и доступные факты SVG. Он не является новым конфигом для
выполнения, списком распознанных сервисов или оценкой их состояния.

Реализованы формат, capture-only запись фактов расчёта, сборка снимка,
сборщик SVG и подключение к React/browser session. Есть отдельный тестовый
получатель; интеграция с рендерером ещё впереди. Обычный путь содержит лёгкое
подключение и опциональные точки записи. Recorder, adapter и SVG-сборщик
находятся в отдельном lazy chunk и не загружаются без принятой session.

## Общие правила

`kind: "svgmodifier"`, `schemaVersion: 1`, producer `svgmodifier-panel`.
Версия описывает формат передачи, не переключает алгоритм расчёта.
Обязательные поля присутствуют всегда; неизвестное значение — `null`,
известная пустая коллекция — `[]`. Ноль и пустая строка не означают отсутствие.

Числа конечны. Время — безопасные целые epoch milliseconds, без смены timezone;
правая граница не меньше левой. Индексы начинаются с нуля, кроме
`line`, `column`, `queryCounter` (с единицы). `generation` также начинается
с единицы. Все ID — строки; panel ID — неотрицательное безопасное целое.

Записи верхних коллекций имеют уникальные ID **внутри своей коллекции**.
Внутренние ID детерминированы для одного снимка, но не обещают стабильность
после изменения конфигурации. Исходные SVG ID, draw.io cell ID, имена полей
и query refId не заменяются такими ссылками.

Нет исходных временных рядов, полного SVG/XML/YAML, DOM-объектов, функций,
приватных настроек datasource или учётных данных. Поля с текстом/ссылками —
недоверенные данные; получатель не исполняет формулы, HTML или ссылки.

## Состав данных

| Поле               | Что означает                                                                                                          |
| ------------------ | --------------------------------------------------------------------------------------------------------------------- |
| `producer`         | ID и версия сборки плагина                                                                                            |
| `panel`            | ID, текущий `svg/grid/table` и доступный title; `table` сохраняет существующее значение настройки, не вводит новый UI |
| `observed`         | Поколение, `Done/Error`, фактическое окно панели и время расчёта; это не время последнего измерения                   |
| `evaluationStatus` | `evaluated/invalid_configuration/failed`: технический итог, не здоровье панели                                        |
| `configuration`    | Статусы YAML/SVG, нормализованные правила и связанные ошибки                                                          |
| `elements`         | Элементы, к которым применяются правила, назначения результатов и победитель                                          |
| `metrics`          | Успешные результаты и неудачные попытки выборки/расчёта, не только победители                                         |
| `expressions`      | Формулы плагина, использованные скалярные входы и результат                                                           |
| `diagnostics`      | Все обнаруженные проблемы, независимо от настройки tooltip                                                            |
| `diagram`          | Структура, текст, видимое оформление, геометрия и явные отношения рисунка                                             |

### Правила, результаты и источники

`configuration.rules[]` содержит исходный selector, подготовленные
`attributes`, исходные `authoredAttributes`, реальные `elementIds` и `source`.
Варианты одного правила для разных элементов сохраняются отдельно: подготовка
может выбрать разные ссылки из массива или применить schema из selector.
Индексы metrics/query относятся к подготовленному attributes; исходные
декларации до этой подготовки не теряются в authoredAttributes.
Неверное декларативное значение (например, строка вместо порога) остаётся
JSON-значением с диагностикой. Оно не делает структуру снимка невалидной.
Не найденный selector не создаёт фиктивный элемент.

`source` хранит страницу, путь, координаты ошибки, индексы и имена query,
если они известны. Неизвестные координаты — `null`; строки/столбцы
исходного текста начинаются с единицы.

У метрики `ruleId/metricsIndex/queryIndex/queryCounter` указывают происхождение.
`selection` отличает выборку по `refid`, `legend` или обоим ключам.
Значение `none` означает query без способа выбора, а не попытку поиска legend.
`selectors` — использованные условия выбора; `sources` — реально выбранные
источники. При двух отдельных суммах одного query сохраняются две записи с
общим queryCounter, а не выдуманная общая сумма.

`sources[]` сохраняет исходные refId, legend, fieldName, frameName, labels,
доступные индексы и публичные uid/type/name datasource. `valueCount` — число
входных значений выбранного поля (для scalar — переданных reducer);
`fromMs/toMs` — доступные временные границы этих
входов; `value` — скаляр после reducer, не массив точек. У суммы здесь остаются
отдельные слагаемые. Если результата/metadata нет, соответствующие поля — `null`.
Число значений и временные границы фиксируются при расчёте, не восстанавливаются
из изменяемого frame позже. Datasource metadata берётся только из уже доступных
данных; неоднозначный target или dashboard datasource не выдаётся за исходный
datasource другой панели. Новые запросы metadata не выполняются.

`label/title` не заменяют исходные имена. `settings` сохраняет эффективные
настройки расчёта, оформления, фильтра, порогов и суммирования. Содержимое
settings/attributes — JSON-данные, не произвольные runtime-объекты.
Если неизвестный calculation вызвал существующий fallback на last, settings
сохраняет декларацию, а source.calculation — реально выбранный reducer.

`availability` и `kind` независимы:

- доступный `scalar` имеет `scalar`, недоступный — `null`;
- доступный `table` имеет `table`; при ошибке разрешено сохранить известные
  колонки/строки, но недоступная таблица не может быть победителем;
- `unresolved` — неудачная выборка неизвестного типа, оба результата `null`.

`scalar` содержит неокруглённое value, отдельное displayValue, level, color,
индекс выбранного порога и след проверок. След фиксирует уже выполненные
проверки: условие/сравнение дали true, false, ошибку или не выполнялись;
`not_present` означает отсутствие condition. Ошибка не подменяется false.
Выбранный порог — последний совпавший в этом следе. У каждой проверки есть
inputs: реально использованные скалярные входы condition с refId, полем,
reducer и доступностью; при отсутствии/невыполнении condition массив пуст.
Эти входы не смешиваются с отдельными plugin expressions. Повторного исполнения нет.

### Привязки к элементу

`elements[].id` — исходный SVG ID. `diagramItemId` связывает его с рисунком,
если тот доступен. `title` берётся из применимых правил, `label` — собственный
текст элемента, а не название ближайшей подписи.

`ruleResults` сохраняет назначения и winner отдельно для каждого правила.
Общий `winnerMetricId/winnerRowIndex` принадлежит `selectedRuleId`.
Для скалярного победителя индекс строки — `null`; для таблицы он совпадает
с `table.winningRowIndex`. Недоступный результат не может быть победителем.

`noData` передаёт решение действующего evaluator, не выводится из серого
цвета. Соседняя отсутствующая метрика не отменяет доступного красного результата.
Неудачная попытка autoConfig может иметь пустые elementIds: привязка к соседнему
индикатору не выдумывается. У статической фигуры без правил нет искусственной
метрики или noData; она представлена только в diagram.

### Таблицы

`columns` сохраняет исходные имена и доступные типы; имена могут повторяться.
`rows` идут в порядке результата расчёта, до сортировки tooltip.
`sourceIndex` — исходный индекс строки до фильтра. `values` — исходные JSON-типы,
`displayValues` — отдельные строки отображения либо `null`, если они неизвестны.
Оба массива имеют ширину columns.

Непредставимая ячейка заменяется на `null` с `cellIssues`: индекс колонки
и ссылки на причины. Обычный исходный null не требует такой записи.
Непригодное число не превращается в ноль.

`thresholdColumnIndex` и `winningRowIndex` — индексы в массивах этого ответа.
Значение, уровень и цвет берутся из `decision` одной строки. Таблица без
пороговой колонки доступна для чтения, но не имеет row decisions или winner.
При ошибке расчёта уже известные строки и их диагностика сохраняются.
`rowFilterStatus` сообщает, успел ли существующий проход применить фильтр:
`applied`, `not_evaluated` либо `incomplete`. При раннем отказе известные
необработанные строки также сохраняются, но их displayValues/decision неизвестны.
Фильтр для экспорта заново не выполняется. Вложенные JSON-ячейки копируются при
обработке строки, чтобы изменения frame до UI commit не меняли факты расчёта.

### Формулы и диагностика

Формула сохраняется как текст вместе с входами, reducers, доступностью и
неокруглённым результатом. У недоступного входа/выражения value — `null`.
RefId формулы или её входа — query identity, не внутренний ID метрики/панели.
Если формула пропущена (например, её refId уже занят входным запросом),
результат unavailable/null и диагностика `EXPRESSION_NOT_EVALUATED` не дают
выдать входное число за результат невыполненной формулы.

### Где собираются факты

`FieldSources` хранит происхождение отдельно от рабочего DataFrameMap.
`EvaluationTrace` принимает факты из текущего прохода: попытки query,
применённый reducer, проверки порогов/условий, строки, результаты формул
и назначения после selector/autoConfig. `buildSnapshot` связывает их ID,
нормализует JSON и отделяет результат от изменяемых объектов расчёта.
Он не вызывает evaluator или функции расчёта повторно.

Recorder передаётся опциональным аргументом. Без него нет индексов происхождения,
копирования ячеек, списков проверок или чтения request targets для экспорта.

Диагностика содержит код, severity, сообщение, source и ссылки на известные
правила/метрики/элементы. Неизвестные связи — пустые массивы. Severity сообщения
не заменяет level метрики. Коды — строки: новые причины не требуют новой версии
формата, если структура и семантика полей прежние.

### Рисунок и оформление

`diagram.status` различает rendered, not_rendered, invalid и missing.
У rendered есть viewport и система координат `svg-viewport-css-pixels`:
bounds выражены в CSS pixels относительно SVG viewport после transform/viewBox,
его начало — (0, 0). Это геометрия данного отображения, не стабильные ID.

При неотрисованном SVG можно сохранить исходные ID/тексты/отношения, но
viewport, coordinateSpace, измеренные bounds/visibility — null, paints — пустые.
Экспорт не переключает режим панели и не рендерит скрытый SVG ради измерений.

В `items` находятся объекты/группы рисунка с исходными svgId/cellId,
тегом, доступным sourceKind и порядком. parentId — структурный родитель среди
записей, не бизнес-группа; циклы недопустимы. authoredText сохраняется отдельно
от текущих textFragments. Фрагменты не теряют границы строк и могут не иметь ID.

`paints` отделяет наблюдаемое оформление отдельных фигур от цвета-решения
метрики. nodePath — путь индексов дочерних элементов внутри объекта, `[]` —
сам объект. fill/stroke/textColor содержат CSS и доступный RGBA; RGB — 0…255,
alpha — 0…1. none/градиент не получают искусственный RGBA. opacity и
fillOpacity/strokeOpacity сохраняются отдельно, не перемножаются с alpha.
Это не обещание восстановить каждый пиксель с учётом фильтров и наложений.
В paints.markers отдельно сохраняются наблюдаемые CSS marker-start/mid/end
(`none`, URL либо null, когда значение неизвестно). Они доступны и у обычного
SVG без embedded model, не требуют записи в connections.

`links.declarations` сохраняет заданные значения и их происхождение
(`svg` либо `rule` с ruleId), `applied` — текущий href отдельно.
Несколько правил/ссылок не схлопываются в ссылку победителя.

`connections` сохраняет только явные source/target из доступной draw.io model
с `origin: "drawio"`. itemId может быть null, если объект не разрешён;
исходный cellId/svgId при этом остаётся. markers.start/end здесь — исходные
типы наконечников из draw.io model, отдельно от CSS markers в paints. Это факты рисунка,
не направление бизнес-зависимости. Нет модели — нет придуманных связей или
требования добавить новую разметку. Имена/геометрия не используются для догадок.

### Как собирается рисунок

`prepareDiagram(sourceSvg)` читает исходный SVG в отдельный XML-документ
и асинхронно разбирает его необязательный `content`. Это именно исходная
строка: обычный `initSVG` удаляет этот атрибут перед отображением.
Исходный документ не вставляется в UI, ссылки/скрипты/изображения не загружаются.

`collectDiagram({ source, root, mode, rules })` синхронно читает фактический
SVG после применения обновления. `attachDiagram(snapshot, capture)` добавляет
его факты и диагностику к результату `buildSnapshot`, не меняя расчёт.
Вызывающая session должна передавать source/root/rules/snapshot одного поколения;
сам сборщик не отслеживает жизненный цикл React.

Live-текст читается из SVG text/tspan и HTML внутри foreignObject, включая
фактические переносы строк. Невидимый текст и невыбранная ветка switch не
становятся видимыми подписями. Собственная подпись элемента берётся только из
его потомков; соседний заголовок не присваивается ему по расположению.
Исходные подписи остаются отдельно даже после label-replace. В grid/table
live-фрагменты пусты, исходные подписи доступны в authoredText.

Группы и обёртки ссылок сохраняют структурное родительство и opacity;
разноцветная группа не получает искусственную общую заливку. Paint относится
к конкретной фигуре/текстовому узлу. Для use доступен экземпляр и его bounds,
но не содержимое закрытого resource/shadow tree: paints пуст, есть
`CAPTURE_USE_PAINT_UNAVAILABLE`. Изображения не проходят OCR, defs не становятся
отдельными отображаемыми объектами.

Metadata поддерживает mxGraphModel и mxfile с одной diagram: XML, escaped XML,
CDATA либо base64 → raw DEFLATE → URL-decoded XML.
Используется нативный DecompressionStream, дополнительного декодера в bundle нет.
Если он недоступен, SVG-факты остаются, а metadata получает диагностику ограничения.
Формат описан в [справке draw.io](https://www.drawio.com/docs/reference/diagram-generation/).

Разрешение конца связи требует точного уникального data-cell-id в исходном
и отображаемом SVG. Префикс SVG ID, название или геометрия не заменяют эту привязку.
Несовпадение, повтор ID, неизвестный конец, повреждённая модель и несколько
страниц дают диагностику; исходный endpoint cellId сохраняется, внутренняя
ссылка остаётся null. Полный XML, labels и произвольные свойства metadata
не переносятся в ответ. parentId описывает DOM, не скрытые бизнес-группы.

Внутренние защитные лимиты сборщика:

- исходный SVG — 8 Mi UTF-16 code units; обход — 50 000 узлов, глубина 256;
- сумма экспортируемого authoredText — 1 000 000 символов, отдельно такой же
  лимит входного live-текста; вложенные группы учитываются в сумме;
- metadata — 4 MiB внешнего UTF-8, 8 MiB после распаковки, 20 000 cells.
  Бюджет распаковки проверяется до URL/XML decoding, поэтому percent-encoding
  тоже занимает место.

Превышение лимита DOM/текста завершает capture ошибкой, а не возвращает
успешный префикс. Превышение metadata-бюджета отключает только отношения
из этой модели с диагностикой. DTD/ENTITY внутри metadata и пользовательские
сущности SVG запрещены; обычный внешний SVG DOCTYPE не загружается.
Это дополнительные пределы работы сборщика, не замена байтового лимита
полного JSON в receiver.

Браузерные проверки запускаются отдельно:

```bash
npm run test:capture:diagram
```

Нужен Chromium установленной версии Playwright. Harness компилирует
самостоятельный тестовый entry во временный каталог, вызывает реальные SVG
операции плагина и запрещает сеть. Это проверка layout/CSS, не Grafana e2e.

## Проверка получателем

### Подключение producer к панели

`useCaptureSession` подключается в layout effect и закрывает принятый handle
при unmount/смене panel ID. Getter-ы hook/handle, connect и вызовы handle
изолированы от UI. Неисправный принятый handle закрывается насколько возможно,
чтобы не оставлять лишний активный instance. Hook после готовности панели
не обнаруживается polling-ом: его нужно установить до навигации.

`usePanelData` начинает поколение до асинхронной работы, в том числе для
Loading/NotStarted. Старые frames в этих состояниях не публикуются.
Только принятая session загружает `svg-capture.js` и создаёт trace.
В capture-режиме первый расчёт ждёт загрузки этого модуля, чтобы не выполнять
формулы второй раз ради экспорта. При ошибке загрузки capture получает
безопасный код, а обычный расчёт продолжается без trace.

Trace связывается с уже подготовленными правилами по их исходному source;
повторной подготовки selectors нет. `guardTrace` изолирует ошибки recorder,
включая чтение дополнительных metadata: первый сбой отключает запись и
завершает capture ошибкой, не подменяя метрики ошибками расчёта.
Ни формулы, ни пороги, ни выбор победителя для этого повторно не выполняются.

Provider публикует после layout effects дочернего SVG, когда его операции
уже применены. Для grid/table и invalid SVG есть тот же terminal path без
ожидания несуществующего рисунка. Корень SVG сохраняется отдельно от XML
Document после переноса в DOM: смена YAML и повторный mount не теряют элементы.
Resize начинает новое capture-поколение с теми же расчётами и новыми bounds.
Смена данных, времени, SVG/YAML или instance отменяет старую публикацию.

### Тестовый receiver и проверки в Grafana

`tests/capture/receiver-entry.ts` экспортирует test-only получатель.
Он устанавливается через Playwright addInitScript до навигации,
проверяет identity/generation, строит ограниченную immutable JSON-копию
и считает точный UTF-8 размер без предварительной полной сериализации.
Неверный JSON, accessor, функция toJSON, цикл или несовместимый payload
не становятся успехом. Обычное JSON-поле с именем toJSON остаётся данными.
Огромный массив отсеивается до перечисления ключей; общее обнаружение ключей
объекта и произвольные Proxy traps нельзя прервать этим бюджетом.

Получатель не входит в runtime плагина и не заменяет будущий renderer bridge.
В unit-тестах строгая schema/reference проверка подключается callback-ом;
в browser harness полный снимок дополнительно валидируется на стороне Node.
Сам плагин не импортирует JSON Schema/Ajv в UI.

```bash
GRAFANA_URL=http://localhost:PORT npm run test:capture:plugin
```

Указанная тестовая Grafana должна содержать собранный плагин и позволять
создание datasource/dashboard. При необходимости задаётся GRAFANA_AUTH_TOKEN.
Harness создаёт уникальные синтетические ресурсы и удаляет только их в finally.
Ответы /api/ds/query фиксированы; frontend, расчёты и SVG-операции настоящие.
Проверяются отсутствие lazy chunk без capture, JSON и UI после обновления,
resize, grid/ошибки конфигурации/данных, отказы hook/chunk и предел ответа.
Это не проверка Grafana → renderer HTTP transport и не замер производительности.

### Требования production-получателя

Проверки выполняются последовательно:

1. JSON-safe данные, версия/kind/producer и структура по JSON Schema.
2. Состояния, уникальность ID, разрешимость внутренних ссылок, согласованность
   двусторонних назначений и winner (включая null), диапазоны времён/индексов
   относительно известных массивов правил/queries, ширина таблиц, отсутствие
   циклов parentId. Исходные внешние cellId/refId могут не разрешаться.
3. Panel ID из запроса, активные instance/generation и факт завершения.
4. Полный UTF-8 размер; превышение — явная ошибка, не успешное усечение.

JSON Schema проверяет структуру, но **сама по себе не доказывает** пункты 2–4.
[Test-only checker](../src/components/capture/testing/validateSnapshot.ts)
фиксирует state/reference/index/size-инварианты для примеров, не является
защищённым от произвольного входа production bridge. В частности, не проверяет
активность instance/generation и не выполняет ограниченное построение JSON.
Размер проверяется и до передачи больших данных; транспорт дополнительно
ограничивает полный ответ вместе со своей оболочкой.

## Пассивный browser protocol

Получатель устанавливает `window.__SVG_MODIFIER_CAPTURE_V1__` **до навигации**.
Плагин не создаёт hook, endpoint, polling или сетевой канал экспорта.

`connect({producerId, producerVersion, panelId, instanceId})` возвращает
`CaptureSessionV1` либо null. Instance обозначает конкретное монтирование,
не только panel ID. Session предоставляет:

- `protocolVersion: 1`, `maxPayloadBytes` — согласованный лимит UTF-8 payload;
- `begin({generation, effectiveFromMs, effectiveToMs})` — инвалидирует прошлый
  terminal result до начала нового run;
- `publish(generation, build)` — синхронная ленивая фабрика полного снимка;
  receiver вызывает её только для текущего instance/generation;
- `fail(generation, {code, message})` — техническая невозможность capture;
- `close()` — завершает instance, поздние результаты не принимаются.

Publish происходит после применения UI-результата того же поколения.
Receiver сохраняет ограниченную JSON-safe копию, не изменяемые объекты React.
Снимок с отсутствующими данными/ошибкой YAML — штатный publish, не fail.
Loading/NotStarted не публикуют старые frames, Streaming пока не поддержан.
Несколько активных подходящих instance — ошибка неоднозначности.
Работа внутри iframe требует receiver в контексте producer, не только top window.

Отсутствующий/несовместимый hook и исключения getter/connect/callback не ломают
UI. Trace, тяжёлый adapter, сериализация и чтение DOM/styles/metadata включаются
только для принятой session. Новый плагин со старым receiver работает как раньше.
